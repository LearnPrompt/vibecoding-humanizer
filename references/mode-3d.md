# 3d 模式：场景去 AI 味

由 [SKILL.md](../SKILL.md) 路由到这里。适用于 Three.js、Blender、glTF 场景、3D 动画和可交互 3D 建模。网页里的 3D 展示，场景本身按本文件，周围的文字与控件按 [ui 模式](mode-ui.md)。

尊重用户的工具约束。作者案例里首版限定 Three.js、优化阶段才允许 Blender，那是那次测试的条件，不是本模式的硬要求；不要为了套规则强制安装新工具。

## 先结构，后材质灯光

把机制和资产分开：先定几何和拓扑（素模/clay 阶段就能看出比例、接触和悬浮问题），确认后再单独调材质与灯光。用一条提示语包办所有环节，最容易出现「每样东西都有，但每样都不对」。

## 识别条目

### 1. 物理关系不成立

**识别信号**：树、石头、建筑浮在半空；第一级台阶被抬高、与地面断开；物体互相穿插；人物脚不着地。

**修改**：逐个检查接触面，让物体落地、嵌合或有支撑。场景规划阶段就写明「保留真实的物理性质」。

**何时保留**：奇幻悬浮是明确设定（如浮空岛）时，悬浮的是设定里的主体，不是随手漂着的树。

### 2. 几何是程序化的「玩具感」

**识别信号**：所有东西都是长方体或圆锥；山体是锯齿金字塔；表面完美平整、边缘锐利；同一个模型复制排列。

**修改**：加轻微磨损、表面坑点、边缘倒角、非完美几何；用更贴合物体的形状（折纸鹤用折面，瓦顶用分层坡面）。可用 Blender 处理 Three.js 难做的部分时，让模型判断哪部分适合哪个工具。

**何时保留**：low-poly、voxel、黏土是**主动选的风格**时不改成写实。负面词里的 low-poly artifacts 指的是意外出现的破面和穿帮，不是否定低多边形风格。

### 3. 材质和纹理没有意义

**识别信号**：侧面贴着无序黑线，既不像枯树也不像岩石；所有物体同一种灰；「超清 8K」代替了材质描述。

**修改**：明确材质：matte / glossy / clay / PBR / 真实磨损。同类物体（青砖、瓦、木构）分色分材质。

### 4. 光到处都在亮

**识别信号**：到处发光、没有明确阴影；所有面亮度相近，画面发假。

**修改**：指定灯光，例如 studio three-point、soft box，或单光源 + 明确阴影。合理的灯光能让精度一般的模型也好看很多。

**注意两个环节**：制作 **PBR 贴图**时要求 flat diffuse lighting，**不要把阴影和高光烘焙进贴图**；最终**场景渲染**仍然要有明确光源和阴影。两者不矛盾，不要把前者理解成场景禁用光影。

### 5. 相机是默认正视

**识别信号**：永远是正面平视或默认轨道相机初始角度。

**修改**：如果 Agent 能操作本地建模工具，明确相机：isometric / 35mm / 85mm + 具体角度。交付时给前、侧、后多个视角，而不是一张图。

### 6. 没有风格锚点

**修改**：明确一个锚点，例如 hard surface + chamfer、clay render、或 photoreal with subsurface。参考用多视图（前/侧/后），不是单张图。

## 可复制的提示语片段

- 负面提示词：plastic look, baked highlights, non-manifold, low-poly artifacts, toy-like（风格本身就是塑料或 low-poly 时去掉对应项）。
- 「先只输出几何和拓扑的素模，确认比例、接触和悬浮问题后，再单独调材质和灯光。」
- 「检查所有物体是否落地或有支撑，不允许树木、石块悬空。」
- 生成后用截图指具体问题：「第 3 帧左侧台阶第一级离地」，比「更真实一点」有效。

## 验收

转至少三个角度看接触关系；看一张素模截图确认结构，再看最终渲染确认材质灯光。说明是浏览器实时预览还是离线渲染。只看过一张截图就不说「已无物理 bug」。
