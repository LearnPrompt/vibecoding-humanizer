# 代码动画里的UI去味

只在用户明确涉及代码动画、MG、视频画面或动效作品时使用。普通网页任务不增加视频制作步骤。

## 先判断输出条件

- 交互界面可有展开、选择和按钮反馈；导出视频里的观众不能点开折叠区。必要内容要在画面或后续时刻出现。
- 用代码定义画面随时间变化，再由渲染程序输出帧并编码，是一类常见实现。它共享前端图形与视觉排版基础，但不等于所有动画都是UI页面拼接。
- 画面整洁不能代替运动、镜头、声音和节奏设计。不要把UI的“减少装饰动画”扩成删掉全部叙事运动。

## 修改时重点看什么

1. 保留表达过程、空间关系、数据变化、视线引导和节奏的动作。检查它服务哪一段内容，不统一套250ms或只保留点击反馈。
2. 关键帧看排版、层级、对齐、字幕安全区与遮挡；播放看文字能否读完、镜头是否连贯、切点与声音是否对齐。单张截图不能验证时序。
3. 可以先做一个关键画面和短样片确认方向，再推广；说明已渲染、已播放或仅有设计建议。
4. 用户选择把逐句口播字幕交给剪映等编辑器时，不烧录跟读字幕；仍保留必要的章节标题、概念字卡和文字动画。不要自动扩大为取消全部文字或启动剪映导入。

## 结果边界

没有运行工程就不说“动画已无卡顿”；只有源码检查时不说“成片已验收”；没有对照结果时不报某模型达到另一个模型的百分比。

实现依据可参照 [Lemo-Opuscar技术文档](https://github.com/lemomo-ai/lemo-opuscar/blob/413a6bd6d78ebd3bdd5abaec9538a26867f890df/TECHNIQUE.md) 与 [Remotion核心概念](https://www.remotion.dev/docs/idea)。这些说明技术路线，不证明特定提示词或模型的视觉效果。

## 风格改编：保留核心，说明代价

来源：[Lemomo原文](https://x.com/lemomo_ai/status/2113195080517562646)，本轮重读旧保存的完整正文与八张静态图；未完整观看文中18个视频。

- 先明确用途、受众、画幅、品牌与输出方式，再选参考风格。
- 区分不改变风格本质的可变项、会改变性格的材质/镜头等项，以及决定风格身份的核心。例如纸面工程线稿改成光滑3D，就不只是换颜色。
- 用“原方案—新方案—代价”说明改编：换竖屏可能重排主次，换中文可能改变字体比例，增加3D可能改变材质和镜头逻辑。
- 先做关键画面和短样片，确认后再扩成整片。迁移到UI时对应核心页面先验证，不能直接把视频流程强加给产品界面。

图里的材质词：Clay／黏土、Plastic／塑料、Glass／玻璃、Chrome／镀铬。这些是示例风格预览，不是所有页面应同时使用的四种材质。原图个案的固定改动数量、字体和帧率也不是通用标准。
