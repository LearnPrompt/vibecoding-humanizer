# html 模式：代码动画与 HTML 动态海报

由 [SKILL.md](../SKILL.md) 路由到这里。覆盖两类产物：

- **代码动画**：用代码（Canvas、SVG、WebGL、DOM + JS/CSS）定义每一帧，再由浏览器或渲染器逐帧输出、编码成视频。细节规则见 [code-animation.md](code-animation.md)。
- **HTML 动态海报**：一张图里每个元素独立成层，标题、图注和数字是真文本，边框等矢量元素用 SVG，简单动效用 CSS。

HTML 只是实现方式。如果目标其实是网页/应用界面，以 [ui 模式](mode-ui.md) 为主；含 SVG 元素时，矢量部分看 [svg 模式](mode-svg.md)。

## 代码动画的识别条目

### 1. 一眼就是「会动的 PPT」

**识别信号**：大面积留白 + 左上角小号英文说明标签；整条片子字形几乎一样；每一幕都是同样时长、同样方式的转场。

**修改**：去掉没有信息作用的英文小字；用字重、字号对比和排版位置建立主次；转场随内容变化（擦除、斜切、粒子爆发），节奏有快有慢、有停顿。

**何时保留**：HUD、时间码、章节编号如果承担叙事或定位作用，可以保留，并统一做成一套系统。

### 2. 颜色和字号没有系统

**修改**：开工前定下几种颜色各自的用途（背景、主文字、强调、粒子）和几档字号；不要每一幕换一套。

### 3. 定位不准

**识别信号**：logo 里的圆环细微超出外框；像素动画错位；元素对齐看起来歪。

**修改**：关键帧逐帧检查对齐；用截图指出具体帧和具体偏差让模型修。

### 4. 只截一张图就宣布完成

**修改**：实际播放。看文字能否读完、切点是否连贯、结束状态是否稳定。

## 动态海报的识别条目

### 5. 文字被画进了图里

**识别信号**：标题、图注、数值是位图或路径，改一个字要重新生成整张图。

**修改**：标题、图注和数字保留为独立 HTML 文本层；照片、图表、装饰分别成层，能单独替换。这样海报可以作为下一篇内容接着修改的模板。

### 6. 简单动效写成了逐帧 JS

**修改**：淡入、位移、循环这类简单动效可以交给 CSS keyframes；SVG 承载线条、边框等矢量元素，缩放后仍清晰。

**边界**：这是编辑性和可维护性上的好处，不是性能保证。不写成「完全不需要 JS」「必然更流畅」「一定更省内存」「自动适配所有平台」。复杂互动仍可能需要 JS；照片清晰度受原素材限制。

### 7. 交付形态不对

**修改**：要发到公众号等平台时，交付静帧和视频/GIF，而不是把 HTML 源文件当成已可发布的素材。提供动效版时考虑 `prefers-reduced-motion` 和静态阅读。

### 8. 署名与来源丢失

**修改**：海报里用到的照片来源、许可署名保留在画面内；能否公开再分发不确定的图片先标出来。

## 不要误用

- 不把 ui 模式的「减少装饰动画」扩大成删掉叙事运动。
- 不默认引入大型动画框架；先用平台已有能力（CSS、Canvas、SVG），确实不够再加。
- 不同长度、不同条件的两版动画不当成严格对照实验。
