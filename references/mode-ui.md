# ui 模式：界面去模板感与审美提升

由 [SKILL.md](../SKILL.md) 路由到这里。适用于网页、App、后台、落地页等**界面目标**；HTML 只是实现方式时同时看 [html 模式](mode-html.md)。下列内容沿用 0.2.0 的八维流程与 13 条诊断，未改规则本身。

## 先选子任务

- **删冗余、去模板感**：使用下方13条诊断规则；直接给模型的完整提示语见 [P1–P6](prompt-library.md)。
- **提升审美、风格迁移、做得更有辨识度**：执行下方八维设计流程，读取 [P7–P14](prompt-library.md)、[官方前端审美完整英中提示](anthropic-prompts-en-zh.md) 与 [风格词和参考选择](aesthetic-reference.md)。不要仅删卡片和文字就宣布完成。
- **查原句、要中英文对照**：读 [英文原句与中文对照](english-originals-zh.md) 和 [新增来源核读](expanded-sources.md)。中文原帖就是中文；给中文规则另写英文时必须标为编辑翻译。
- **查是否收全**：读 [来源覆盖与缺口](source-coverage.md)。收藏已找到、正文已读、图片已读、提示语已提取和效果已验证是不同状态。
- **做视频或代码动效**：这是 html 模式的任务，转读 [html 模式](mode-html.md) 与 [代码动画适配](code-animation.md)，保留镜头、节奏、时序和叙事所需信息。

## 审美提升：八个维度落实到画面

先明确这页的对象与主要任务，再选参考并写下准备迁移的视觉特征。已有品牌系统时沿用；允许大胆、有辨识度的设计，不默认白底极简。先用真实内容做一个关键画面，确认后再扩展。

| 维度 | 要做的设计判断 | 怎么核对 |
|---|---|---|
| 字体 typography | 字体气质、中文回退、字重和大小比例、行长与行距共同建立阅读节奏 | 看真实长短标题、正文和数字，不只看占位英文 |
| 留白 whitespace | 用组内/组间距离、密度变化和边距表达内容关系 | 同类区域节奏一致，重点有空间，长内容不溢出 |
| 视觉层级 visual hierarchy | 明确焦点、网格、阅读顺序和主要动作；可用不对称或跨栏建立张力 | 第一眼能辨认主次，窄屏不打乱阅读顺序 |
| 配色 color | 稳定语义角色后选择适合内容的色相、明暗、对比和材质 | 重点突出，状态不冲突，纹理不淹没文字 |
| 动效 motion | 明确对象、触发、轨迹、节奏、停顿、结束状态 | 实际播放，判断是否引导注意或表达变化；处理不适合持续运动的场景 |
| 微交互 micro interaction | 让操作的反馈、加载、错误、成功与可操作性一致 | 实际点按、键盘和触屏适配；不只检查hover |
| 响应式 responsive | 为窄屏重新安排密度、顺序、换行和交互 | 在真实视口检查，不把桌面整页等比缩小 |
| 辨识度 originality | 从主题内容中提炼一套主视觉、图形、材质或动作语言 | 能说明设计为何属于这个项目，而不是只换品牌色的模板 |

维度来自S4英文提示词；表中实现判断是编辑适配，不是逐字翻译。官方前端审美来源进一步补充了连贯主题、字体对比、关键入场编排及背景纵深；其禁止字体、3倍字号、外链字体和固定主题是示例原句，不作为本Skill的通用硬规则。风格案例与动效词典帮助具体化选择，不强制打开所有资源或安装第三方Skill。

完成后按选定目标复查前后画面与关键操作。说明改善了哪些维度、保留什么、哪些仍未验证；不追求无限自审或虚构审美评分。

去冗余的核心原则来自 Zihua（@luinlee），也是用户本次截图里的指令：

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

对应中文：**避免不必要的次级标签和说明，让布局本身把关系解释清楚。**

这不要求删掉所有文字。先分清重复解释、必要标签、错误信息、风险提示和输入要求。

## A. 用说明文字代替设计

### 1. 同一信息被反复解释

**识别信号**：标题、副标题、卡片说明反复说同一件事；页面像说明书。

**问题**：文字没有增加信息，反而挤占操作和内容。

**修改前**：标题“素材库”，下面写“在这里查看和管理您的全部素材”；按钮“上传素材”，旁边再写“点击此按钮上传”。

**修改后**：保留“素材库”和“上传素材”；用列表、分组及空状态说明表达当前内容。上传格式、容量限制和报错仍保留。

**何时保留**：概念陌生、操作后果不明显、输入有约束或错误需要解决时。不要把必要帮助只藏在鼠标悬停里，移动端和键盘用户也要能找到。

**依据**：S1、S2-2。这是本 Skill 的首要检查项。

### 2. 没有信息作用的英文小标题和分隔装饰

**识别信号**：每个中文标题上方都放一行英文大写词；文案习惯性塞中点或符号。

**问题**：装饰文字重复主标题，或让短标签难以扫描。单个英文词、中点并不足以判定有问题。

**修改前**：“MEDIA LIBRARY / 素材库 / 你的素材管理空间”。

**修改后**：只留“素材库”；真实的分类、路径或内容类型可以作为辅助信息。

**何时保留**：英文是用户使用的分类、品牌表达或额外上下文；中点能清楚分开时间、作者等不同字段时。不按“见到符号就删”的规则处理。

**依据**：S3、S2-1；中点禁令原为个人偏好。

### 3. 文案没有对准这页的使用者

**识别信号**：普通操作充满抽象词、造词或口号；按钮不说明动作。

**问题**：用户要先翻译界面文案，才能决定做什么。

**修改前**：“开启你的多模态灵感赋能旅程”。

**修改后**：按真实功能写“新建项目”或“上传素材”；没有对应功能时不要捏造入口。

**何时保留**：专业用户确实使用该术语，或名称已属于品牌和产品定义时。不要把所有专业词改成含糊口语。

**依据**：S2-3。

## B. 内容关系被模板外观盖住

### 4. 每个数字、每段话都单独套框

**识别信号**：相关统计拆成一排独立小卡；同一组信息被多层容器切碎。

**问题**：视觉边界比信息关系更抢眼。

**修改前**：“全部／处理中／待检查／已完成”各自一张带阴影的小卡。

**修改后**：相关统计放进同一分区，用位置、间距、对齐和细分隔区分；不同任务或可独立操作的区域再保留容器。

**何时保留**：卡片本身是可选择、可拖动、可进入的对象，或各项确有独立结构时。

**依据**：S2-10 与原帖统计页前后图；合并分区是从配图提炼的做法。

### 5. 圆角、阴影和彩边到处叠加

**识别信号**：每层容器都带强阴影；卡片左侧彩条没有状态意义；边框、底色、阴影同时强调同一层级。

**问题**：装饰把所有东西抬到同一优先级。

**修改前**：外框阴影、内框阴影、每条记录再套彩色圆角框。

**修改后**：保留能表达层级、交互或状态的必要边界，弱化多余装饰；真正的浮层仍要与背景分开。

**何时保留**：品牌明确使用相关外观、浮层需要区分、颜色表达真实状态时。边框是否用0.5px由目标设备的清晰度决定，不设成通用规定。

**依据**：S2-6、S2-10、S2-R。

### 6. 颜色没有稳定的用途

**识别信号**：相同状态在不同地方用不同颜色；无关元素同时争抢重点。

**问题**：颜色不能帮助用户理解状态或主次。

**修改前**：随机给每张统计卡分配一个亮色，真正的错误却和装饰共用红色。

**修改后**：确定背景、文字、边界、主操作和状态的角色，统一同类含义的用色。沿用现有品牌及设计变量。

**何时保留**：渐变、玻璃、颗粒和多色本身不是错误；艺术风格或分类确有用途时可以保留。Radix Colors可作角色划分参考，不强制替换所有颜色或新增依赖。

**依据**：S2-4；S6配图说明不能把“禁渐变”当去味办法。

### 7. 字号不断增加，信息主次仍不清楚

**识别信号**：相近内容有很多尺寸，每个小标题都争当大标题。

**问题**：字号数量增加，但阅读顺序没有变清楚。

**修改前**：同一屏标题、说明、统计、标签随手设多个相近字号。

**修改后**：用少量主要字号，再以字重、间距和对比建立主次。三四档可作为普通页面的整理起点，而非全站上限。

**何时保留**：编辑型排版、复杂产品和大屏确有更多层级时。正文、辅助字及视频字幕要按实际观看尺寸判断，不强制12px最小字。

**依据**：S2-8。

### 8. 几何上排齐了，看起来仍歪

**识别信号**：图标与文字看起来不在一排；内外嵌套圆角与间距不协调。

**问题**：可见轮廓和文字基线的关系没有处理好。

**修改前**：图标盒子居中，但图案偏上；内外框使用同样大圆角，间隙不均。

**修改后**：按实际可见轮廓调整图标与文字；结合内边距协调嵌套圆角。不要为了凑一个公式改坏布局。

**何时保留**：图形有意偏置，或非对称布局服务内容时。

**依据**：S2-5。

## C. 交互和动效没有服务任务

### 9. 用户被迫做很多没必要的选择

**识别信号**：低频设置占据首屏；完成同一任务前要经过重复确认或选择。

**问题**：用户的注意力被支线消耗。

**修改前**：上传前先展示所有高级设置，用户无法判断哪些必须填。

**修改后**：突出必需输入，把低频设置放在可发现的按需展开区；必要选择放在用户实际决策的位置。

**何时保留**：涉及授权、付费、删除或不可逆后果的确认仍应保留；不能替用户悄悄做决定。

**依据**：S2-9；保留关键确认属于本次实施边界。

### 10. 每个元素都要飘、弹或逐个入场

**识别信号**：内容还没读，先等一串入场；无操作时装饰不停运动。

**问题**：动作没有新增反馈或信息，还可能打断阅读。

**修改前**：所有卡片依次弹出，鼠标移过任意区域都放大。

**修改后**：保留与操作、状态和视线引导有关的动作，减少无用途的运动；按组件调节时长和缓动。

**何时保留**：动画本身是作品、教学、叙事或数据变化的一部分时。ease-out／250ms只是原帖的起点建议，不统一套用；代码动画另看专门参考。

**依据**：S2-7；S5仅提供动效参考入口。

## D. 修改方式本身变成新的模板

### 11. 只有“高级一点”，没有具体参照

**识别信号**：需求只含“高级、现代、去AI味”；改完只剩另一套通用模板。

**问题**：模型没有拿到任务、取舍或视觉方向。

**修改前**：“做成苹果风，越高级越好”。

**修改后**：结合用户给的图或页面，说明要借鉴布局、字体比例、留白、配色或纹理的哪几项，先改一个核心画面。

**何时保留**：用户已明确品牌和设计系统时不另找风格；参考图也不意味着可以照搬品牌、图片和文案。

**依据**：S5、S6为参考素材；具体迁移方法是编辑适配。

### 12. 把“获奖级”和无限自审当验收

**识别信号**：要求覆盖所有指令、无条件循环、直到没有任何可改善之处；只回复“已优化”。

**问题**：目标无法合理收尾，也未说明用户是否更容易完成任务。

**修改前**：“对标所有获奖站，直到没有提升空间再结束”。

**修改后**：按字体、留白、层级、颜色、动效、微交互、响应式和辨识度检查，优先修影响当前任务的问题；用前后画面和核心操作核对，明确本轮边界与剩余问题。

**何时保留**：获奖作品适合作为特定方向参考，但营销落地页与后台工具的判断标准不同。不继承来源中的“覆盖所有指令”或无限循环语法。

**依据**：S4的英文清单；限定范围和可验收结果是编辑修正。

### 13. 用网页交互规则把动画改坏

**识别信号**：视频只剩按钮反馈；关键信息藏进无法点击的折叠区；只截一张图就宣布时序正常。

**问题**：视频没有网页的交互条件，也需要时间和叙事。

**修改前**：把所有非点击动画删掉；让观众“展开查看更多”。

**修改后**：保留镜头、图形变化和叙事动作；把次要信息安排在合适时刻；关键帧与实际播放都检查。

**何时保留**：真正的交互式作品有相应控件时，按实际交互条件处理。普通UI任务不自动扩展成做视频。

**依据**：E1，来自本次代码动画讨论的编辑适配，不是原帖通用UI规则。

## 哪些情况不必改

- 用户明确选择的风格和品牌表达，本身不算错误。只有一种外观特征，不能据此断言页面由AI生成或质量差。
- 必要的表单标签、状态、错误、风险、价格、权限、来源和输入约束，即使占空间也有用途。不要把它们全部改成不可见的辅助文本。
- 卡片、渐变、圆角、英文小标题、分隔符或动画，只要能说明真实关系或符合明确创作意图，都可以保留。
- 已经清楚、好用的页面不需要为了“执行去味”强行重设计。
